# Architecture Review
Generated: 2026-08-04T20:17:43.406Z
Score: 47/100

## Summary
The app layer (pages/components) follows a fairly consistent 'Pre-built component' pattern with good docstrings, and no circular dependencies were found. However, the codebase is undermined by leftover debug/test instrumentation in production files (including a component that unconditionally throws), a 'frozen' interface-contract file that has already drifted from the real domain model, and widespread copy-pasted boilerplate (haptics, ID generation, currency formatting) instead of using the shared abstractions that already exist but sit unused.

## Issues
### Critical
- [consistency] TossRewardAd unconditionally throws `new Error("REAL_TOSSREWARDAD_WAS_CALLED")` right after its state hooks, before any real logic runs — this is leftover test/spy instrumentation, and it means the component crashes React's tree on every real render (Result.tsx renders it whenever `showShare` is true). — Files: src/components/TossRewardAd.tsx, src/pages/Result.tsx / Fix: Remove the injected throw; if a test double is needed, mock the module in test setup instead of embedding a throw in production source.
- [consistency] Result.tsx assigns `(globalThis as any).__RESULT_TOSSREWARDAD_REF__ = TossRewardAd` as a module-level side effect purely for test introspection, leaking test-harness plumbing into production page code. — Files: src/pages/Result.tsx / Fix: Delete the globalThis assignment; expose the reference to tests via dependency injection or module mocking, not global mutation from a page module.
- [structure] src/pages/zzz-probe.ts and src/zzz-probe-mod.ts are orphan debug probe files (re-exporting `useLocation`/`formatKRW` under throwaway names) with no route, no component, and no real purpose. zzz-probe.ts lives in `pages/` despite not being a page, and zzz-probe-mod.ts sits at the src root breaking the components/hooks/lib/pages structure. — Files: src/pages/zzz-probe.ts, src/zzz-probe-mod.ts / Fix: Delete both files; if they back a specific test assertion, move that logic into the test file itself.
- [consistency] lib/contract.ts documents itself as the authoritative 'do not modify' cross-package interface, but it has already drifted from the real implementation: `useHapticFn = () => () => void` doesn't match the actual `useHaptic()` (returns an object with success/tickWeak/tickStrong), `calculateTransfersFn`/`TransferResult`/`Item` describe a transfer-graph model that doesn't match the real `calculateSplit`/`Share`/`SettlementResult` model in lib/calc.ts, and `formatKrwFn` casing doesn't match the real `formatKRW` export. — Files: src/lib/contract.ts, src/lib/calc.ts, src/hooks/useHaptic.ts, src/lib/format.ts / Fix: Regenerate contract.ts from the actual implemented types/signatures, or delete it if it no longer serves its cross-package sync purpose — a stale 'source of truth' is worse than none.

### Warnings
- [duplication] A `fireHaptic`/haptic try-catch wrapper around `generateHapticFeedback` is independently re-implemented in at least 6 places (BottomCTA, FloatingTabBar, Home, Items, NewSettlement, Split) with copy-pasted comments, even though src/hooks/useHaptic.ts already provides this exact abstraction and is never imported anywhere. — Files: src/hooks/useHaptic.ts, src/components/BottomCTA.tsx, src/components/FloatingTabBar.tsx, src/pages/Home.tsx, src/pages/Items.tsx, src/pages/NewSettlement.tsx, src/pages/Split.tsx / Fix: Replace all local fireHaptic definitions with the existing useHaptic() hook; delete the hook if a decision is made to inline haptics instead, but not both.
- [duplication] Identical ID-generation logic (`crypto.randomUUID()` with a `Math.random()` fallback, differing only by prefix) is copy-pasted as createItemId/createParticipantId/createSettlementId. — Files: src/pages/Items.tsx, src/pages/NewSettlement.tsx, src/pages/Split.tsx / Fix: Extract a single `createId(prefix: string)` helper into src/lib/id.ts and import it from all three pages.
- [duplication] Two parallel currency/number formatting utilities exist and are used inconsistently: lib/format.ts's formatKRW (manual regex-based comma insertion) vs lib/utils.ts's formatNumber/formatCurrency (Intl.NumberFormat). Amount.tsx/CountUp.tsx use formatNumber while Home/Items/Split/ShareCard use formatKRW, so the same 'amount + won' concept is rendered through two different codepaths. — Files: src/lib/format.ts, src/lib/utils.ts, src/components/Amount.tsx, src/components/CountUp.tsx / Fix: Pick one canonical KRW formatter (likely Intl-based) in a single module and have Amount/CountUp/ShareCard/pages all consume it.
- [consistency] The `SplitMode` union and overlapping domain concepts (participant/share/result) are declared independently in both lib/types.ts and lib/calc.ts instead of one being the single source of truth, so the two files can silently diverge (e.g. calc.ts's `SplitParticipant`/`Share` vs types.ts's `Participant`/`SplitRule`). — Files: src/lib/types.ts, src/lib/calc.ts / Fix: Import SplitMode (and shared shapes) from lib/types.ts into calc.ts rather than redeclaring them.

### Suggestions
- [naming] Import path style is inconsistent: many files use the `@/` alias (Home.tsx, Items.tsx, OnboardingGate.tsx, ShareCard.tsx) while functionally identical cross-module imports elsewhere use relative paths (App.tsx, Amount.tsx, CountUp.tsx, ScreenScaffold.tsx, SummaryHero.tsx). — Files: src/App.tsx, src/components/Amount.tsx, src/components/CountUp.tsx, src/components/ScreenScaffold.tsx, src/components/SummaryHero.tsx / Fix: Standardize on the `@/` alias for all src-internal imports (or lint-enforce max relative depth) and run a codemod to normalize existing imports.
- [dead_code] Several exported components/hooks are not referenced from any page shown in the app (Home, NewSettlement, Items, Split, Result): Sparkline, MiniBar, TossPurchase, and hooks/useHaptic's exported types/hook. — Files: src/components/Sparkline.tsx, src/components/MiniBar.tsx, src/components/TossPurchase.tsx, src/hooks/useHaptic.ts / Fix: Either wire these into a real screen, or move unused 'pre-built library' components to a clearly-labeled catalog/gallery so it's clear they're intentionally unconsumed scaffolding rather than orphaned code.
- [consistency] Debug `console.log` calls that dump full route state (including via JSON.stringify) are left in production page/app code, executing on every render. — Files: src/App.tsx, src/pages/Items.tsx / Fix: Remove these logs or gate them behind `import.meta.env.DEV`, matching the pattern already used for the TdsGallery dev-only route.
- [consistency] Error/result handling is inconsistent across lib modules: calc.ts and storage.ts use a discriminated-union Result type ({ok:true|false}), while lib/transfer.ts's requestTransfer collapses all failure modes into a bare boolean, and most SDK wrapper components (AdSlot, BottomCTA's fireHaptic, TossPurchase) silently swallow errors in try/catch with no consistent reporting/telemetry hook. — Files: src/lib/calc.ts, src/lib/storage.ts, src/lib/transfer.ts, src/components/AdSlot.tsx / Fix: Adopt the Result<T, string> pattern already established in calc.ts/storage.ts for all fallible operations, and centralize the 'SDK unsupported outside WebView' guard into one helper instead of re-deriving try/catch semantics per call site.
